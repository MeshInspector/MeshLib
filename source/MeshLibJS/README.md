# MeshLib JavaScript bindings

Generated by [mrbind](https://github.com/MeshInspector/mrbind) from the C bindings, as ES modules (with TypeScript declarations) that call the C bindings compiled to WebAssembly with Emscripten. This covers the whole MeshLib API (the manually written Embind module it replaced covered a part of it). Nothing in this directory is committed except this file and `CMakeLists.txt`:

```sh
make -f scripts/mrbind/generate.mk TARGET=c    # The C bindings and their description JSON (with `C_FOR_WASM=1` when targeting wasm).
make -f scripts/mrbind/generate.mk TARGET=js   # The JS sources in `js/`, and `js/emcc_link_flags.rsp` for the next step. `JS_WASM64=1` generates `js64/` for the 64-bit modules.
```

Then build MeshLib for Emscripten with `-DMESHLIB_BUILD_GENERATED_C_BINDINGS=ON -DMESHLIB_BUILD_JS_BINDINGS=ON` (and `-DMESHLIB_BUILD_MRVIEWER=OFF`, the viewer adds its GL glue and asyncify to every executable), which copies the generated JS to `build/Release/MeshLibJS/js` and links the C bindings and MeshLib into `MeshLibC2.mjs` + `.wasm` (browsers and workers) and `MeshLibC2.node.mjs` + `.wasm` (Node, with the real file system) next to the copy:

```sh
MR_CMAKE_OPTIONS="-DMESHLIB_BUILD_MRVIEWER=OFF -DMESHLIB_BUILD_GENERATED_C_BINDINGS=ON -DMESHLIB_BUILD_JS_BINDINGS=ON" MR_CMAKE_BUILD_OPTIONS="--target MeshLibJS MeshLibJSNode" ./scripts/build_source.sh
```

`scripts/npm/assemble.sh` packs the directory into the `@meshinspector/meshlib` npm package (`-mt` for the multithreaded build).

To use the bindings:

```js
import * as ml from "./build/Release/MeshLibJS/js/index.mjs";
await ml.init();
const mesh = ml.makeCube(ml.Vector3f.diagonal(1), ml.Vector3f.diagonal(-0.5));
console.log(mesh.volume());
```

See `source/MRTestJS` for the tests (`node source/MRTestJS/main.mjs`), and `thirdparty/mrbind/docs/generating_js.md` for what the generated code looks like.
