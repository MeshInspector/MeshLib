# MeshLib JavaScript bindings

Generated by [mrbind](https://github.com/MeshInspector/mrbind) from the C bindings, as ES modules (with TypeScript declarations) that call the C bindings compiled to WebAssembly with Emscripten. This covers the whole MeshLib API, unlike the manually written module in `source/MRWasmModule`. Nothing in this directory is committed except this file and `CMakeLists.txt`:

```sh
make -f scripts/mrbind/generate.mk TARGET=c    # The C bindings and their description JSON (with `C_FOR_WASM=1` when targeting wasm).
make -f scripts/mrbind/generate.mk TARGET=js   # The JS sources in `js/`, and `js/emcc_link_flags.rsp` for the next step.
```

Then build MeshLib for Emscripten with `-DMESHLIB_BUILD_GENERATED_C_BINDINGS=ON -DMESHLIB_BUILD_JS_BINDINGS=ON`, which links the C bindings and MeshLib into `js/MeshLibC2.mjs` + `js/MeshLibC2.wasm` next to the generated JS:

```sh
MR_CMAKE_OPTIONS="-DMESHLIB_BUILD_GENERATED_C_BINDINGS=ON -DMESHLIB_BUILD_JS_BINDINGS=ON" MR_CMAKE_BUILD_OPTIONS="--target MeshLibJS" ./scripts/build_source.sh
```

To use the bindings:

```js
import * as ml from "./source/MeshLibJS/js/index.mjs";
await ml.init();
const mesh = ml.makeCube(ml.Vector3f.diagonal(1), ml.Vector3f.diagonal(-0.5));
console.log(mesh.volume());
```

See `source/MRTestJS` for the tests (`node source/MRTestJS/main.mjs`), and `thirdparty/mrbind/docs/generating_js.md` for what the generated code looks like.
